# Windows USB 摄像头调参与局域网 RTSP 推流教程

本文面向第一次接触摄像头和视频推流的人员，使用成熟的 Windows 图形化软件完成以下工作：

1. 在 Windows 电脑上查看 USB 摄像头画面；
2. 调整曝光、增益、分辨率、帧率和视频格式；
3. 将画面发布成局域网内可访问的 RTSP 流；
4. 在另一台设备上拉流，检查接收系统是否正常。

适用摄像头为 Wasintek UVC USB 摄像头（本项目实测设备的 USB VID:PID 为 `2aad:6373`）。Windows 中的设备名称可能显示为 `Wasintek camera`、`USB Camera` 或 `USB Video Device`，名称不同不代表设备有问题。

> 本教程不要求编写程序。只安装 OBS Studio、MediaMTX 和 VLC 三个现成工具，并修改 MediaMTX 配置文件中的两行文字。

## 一、先看懂最终连接关系

```text
USB 摄像头
    ↓
OBS Studio（看画面、调摄像头、编码）
    ↓  只在本机内部传输
MediaMTX（提供 RTSP 服务）
    ↓
rtsp://推流电脑的局域网IP:端口/路径
    ↓
另一台电脑、手机或甲方自己的系统拉流
```

本教程统一使用以下示例：

| 项目 | 示例值 | 能否自行修改 |
|---|---|---|
| 推流电脑的局域网 IP | `192.168.112.101` | 不能随便填写，必须使用该电脑的真实 IPv4 地址 |
| RTSP 端口 | `8556` | 可以，建议使用 `1024`～`65535` 中未被占用的端口 |
| 流路径 | `camera` | 可以，建议只使用英文字母、数字、短横线，不要用空格或中文 |
| 最终拉流地址 | `rtsp://192.168.112.101:8556/camera` | 由上面三项组合得到 |

**最重要的一点：**端口和路径可以自己决定，但 IP 地址不能凭空编一个。示例中的电脑只有在其真实 IP 确实是 `192.168.112.101` 时，才能使用该地址。

## 二、准备软件和硬件

### 2.1 需要准备

- 一台 Windows 10 或 Windows 11 电脑；
- Wasintek USB 摄像头；
- 一根正常的 USB 数据线；
- 一台用于拉流测试的其他电脑、手机或业务设备；
- 推流电脑和拉流设备连接到同一个局域网；
- 推荐推流电脑使用网线连接路由器，高帧率测试时比 Wi-Fi 稳定。

### 2.2 下载并安装三个工具

只从以下官方页面下载：

1. [OBS Studio 官方下载页](https://obsproject.com/download)：选择 Windows 版本，按默认选项安装；
2. [MediaMTX 官方发布页](https://github.com/bluenviron/mediamtx/releases/latest)：在页面下方 `Assets` 中下载文件名包含 `windows_amd64` 的压缩包；
3. [VLC media player Windows 官方下载页](https://www.videolan.org/vlc/download-windows.html)：按默认选项安装。

绝大多数 Intel 或 AMD 处理器的 Windows 电脑都应下载 `windows_amd64` 版 MediaMTX。不要下载 `linux`、`darwin`、`arm64` 或 `Source code`。

将 MediaMTX 压缩包完整解压到一个固定目录，例如：

```text
C:\CameraRTSP
```

解压后应至少看到：

```text
C:\CameraRTSP\mediamtx.exe
C:\CameraRTSP\mediamtx.yml
```

不要直接在压缩包预览窗口里运行 `mediamtx.exe`。

## 三、连接摄像头并在 OBS 中打开画面

### 3.1 连接摄像头

1. 退出 Windows“相机”、微信、腾讯会议、Teams、浏览器视频会议等可能占用摄像头的软件；
2. 将摄像头连接到电脑的 USB 3.x 接口，通常是蓝色接口或带 `SS` 标记的接口；
3. 等待 Windows 自动完成驱动安装；
4. 打开 Windows 的“相机”应用，确认能看到画面；
5. 确认后关闭“相机”应用。摄像头通常不能同时被“相机”和 OBS 占用。

如果“相机”应用也没有画面，请先检查 USB 线、USB 接口和摄像头权限，不要继续配置推流。

Windows 11 的权限位置通常是：

```text
设置 → 隐私和安全性 → 相机
```

确认“相机访问”和“允许桌面应用访问相机”均已打开。

### 3.2 在 OBS 中添加摄像头

1. 打开 OBS Studio；
2. 第一次启动时若出现“自动配置向导”，可以点击“取消”，本教程会手动设置；
3. 在左下方“场景”区域点击 `+`，新建场景，名称填写“摄像头测试”；
4. 在旁边“来源”区域点击 `+`；
5. 选择“视频采集设备”（英文界面为 `Video Capture Device`）；
6. 选择“新建”，名称填写“Wasintek 摄像头”，点击“确定”；
7. 在“设备”下拉框中选择 `Wasintek camera`、`USB Camera` 或 `USB Video Device`；
8. 看到实时画面后先不要关闭窗口，继续设置下一节的参数。

如果列表中有多个摄像头，可用手遮挡镜头，观察哪一个画面变黑，以确认选中的设备。

## 四、设置分辨率、帧率和摄像头输出格式

在 OBS 的“视频采集设备属性”窗口中进行以下设置：

1. 将“分辨率/FPS 类型”改成“自定义”；
2. 第一次测试按下面的推荐值填写；
3. 点击“确定”；
4. 等待 3～5 秒，确认 OBS 主画面仍然连续显示。

第一次建议使用：

| 选项 | 推荐值 |
|---|---|
| 分辨率 | `1920x1080` |
| FPS | `30` |
| 视频格式 | 优先 `H264`；没有画面时改为 `MJPEG` 或 `MJPG` |
| 色彩空间 | 默认 |
| 色彩范围 | 默认或部分 |
| 缓冲 | 自动检测 |

本型号摄像头已经实测过的常用组合包括：

| 摄像头输出格式 | 可优先尝试的分辨率和帧率 |
|---|---|
| H.264 | `3840x2160@30`、`1920x1080@60/30`、`1280x720@120/60/30` |
| MJPEG/MJPG | `1920x1080@60/30`、`1280x720@120/60/30` |

不要一开始就使用 4K 或 120 FPS。先用 `1920x1080@30` 跑通完整推拉流，再一次只修改一个参数。

> “视频格式”是摄像头通过 USB 送给 OBS 的采集格式；后文的“编码器”是 OBS 送到局域网的最终码流格式。这是两个不同的设置。即使摄像头采集格式选择 MJPEG，最终 RTSP 仍建议编码成 H.264，以获得最好的接收兼容性。

### 4.1 修改后黑屏怎么办

出现黑屏通常表示当前“格式 + 分辨率 + 帧率”组合不被驱动支持：

1. 先把 FPS 改回 `30`；
2. 再把分辨率改回 `1920x1080`；
3. 将视频格式从 `H264` 改成 `MJPEG/MJPG`，或反过来；
4. 仍然黑屏时，将“分辨率/FPS 类型”暂时改回“设备默认”；
5. 关闭其他可能占用摄像头的软件，拔插摄像头后重新打开 OBS。

## 五、调整曝光、增益和其他画面参数

### 5.1 打开摄像头参数窗口

1. 在 OBS 下方“来源”中双击“Wasintek 摄像头”；
2. 点击“配置视频”（英文界面为 `Configure Video`）；
3. Windows 通常会打开带有以下两个页签的摄像头驱动窗口：
   - “视频处理放大器”或 `Video Proc Amp`；
   - “摄像头控制”或 `Camera Control`。

不同 Windows 版本、驱动和语言下，名称与排列可能略有不同。

### 5.2 各参数是什么意思

| 参数 | 作用 | 调太大或调太小的表现 |
|---|---|---|
| 曝光 `Exposure` | 决定传感器接收光线的时间 | 太长会拖影、帧率下降；太短会很暗 |
| 增益 `Gain` | 将传感器信号放大 | 太大会出现颗粒、彩色噪点；太小会暗 |
| 亮度 `Brightness` | 对整体亮度作数字调整 | 过大会发灰、过曝，不能代替正确曝光 |
| 对比度 `Contrast` | 调整明暗差异 | 过大会丢失亮部和暗部细节 |
| 饱和度 `Saturation` | 调整颜色浓淡 | 过大会颜色失真，过小会接近黑白 |
| 色调 `Hue` | 改变整体颜色相位 | 一般保持默认值 |
| 锐度 `Sharpness` | 增强边缘 | 过大会产生白边和噪点 |
| 白平衡 `White Balance` | 修正画面偏蓝、偏黄 | 自动模式可能随场景变化而跳动 |
| 电源频率 `Power Line Frequency` | 减少照明灯闪烁 | 中国大陆一般选 `50 Hz` |
| 变焦 `Zoom` | 数字放大画面 | 放大后视野变小、清晰度下降 |

### 5.3 最简单、最稳妥的调节顺序

1. 先固定现场灯光，并将镜头对准实际要拍摄的场景；
2. 先选好最终分辨率和 FPS，再调曝光；
3. 找到 `Exposure`，取消旁边的“自动”勾选；
4. 从当前值开始小幅调整曝光，让画面亮度合适；
5. 对着运动物体摆手。如果出现明显拖影，就减小曝光；
6. 画面仍然偏暗时，再逐步增加 `Gain`；
7. 增益出现明显噪点后不要继续增加，应改善现场照明；
8. 最后再少量调整亮度、对比度、饱和度和锐度；
9. 点击“应用”，观察几秒，再点击“确定”。

调参原则可以记成一句话：**先用曝光获得亮度，再用少量增益补亮；运动画面优先避免长曝光拖影。**

Windows 驱动显示的曝光刻度不一定等同于 Linux 下的绝对曝光数值，因此不要机械照抄其他系统里的数字。摄像头断电、拔插或重新被程序打开后，部分参数可能恢复默认值；正式测试前应再次检查，并截图保存最终设置。

如果点击“配置视频”后完全没有曝光或增益选项，说明当前 Windows 驱动没有把这些控制项暴露给 OBS。可先在 Windows 更新中检查驱动更新；如果厂家提供 Windows 驱动或调参工具，再安装厂家版本。不要安装来源不明的“万能摄像头驱动”。

## 六、配置 OBS 的最终输出画质

摄像头属性只决定 OBS 收到什么画面，本节决定局域网 RTSP 最终输出什么画面。

### 6.1 设置输出分辨率和 FPS

1. 在 OBS 右下角点击“设置”；
2. 点击左侧“视频”；
3. 第一次测试按下面填写：

| 选项 | 第一次测试值 |
|---|---|
| 基础（画布）分辨率 | `1920x1080` |
| 输出（缩放）分辨率 | `1920x1080` |
| 常用 FPS 值 | `30` |

4. 点击“应用”。

OBS 的输出 FPS 不应高于摄像头采集 FPS。例如摄像头属性是 30 FPS，OBS 输出不要填 60 FPS。

如果摄像头画面没有铺满黑色画布，可在“来源”中右键“Wasintek 摄像头”，选择“变换 → 比例适配屏幕”（英文为 `Transform → Fit to Screen`）。

### 6.2 设置 H.264 编码器和码率

1. 仍在 OBS“设置”中，点击左侧“输出”；
2. “输出模式”先选“简单”；
3. 在“推流”区域设置：

| 选项 | 推荐值 |
|---|---|
| 视频编码器 | 优先选择名称含 `H.264`、`NVENC`、`QuickSync/QSV` 或 `AMD/AMF` 的硬件编码器；没有时选 `x264` |
| 视频码率 | 1080p30 填 `6000 Kbps`；1080p60 填 `8000 Kbps`；720p30 填 `4000 Kbps` |
| 音频码率 | 保持默认即可；本测试不需要声音 |

4. 点击“应用”，再点击“确定”。

如果硬件编码器报错，改用 `x264`。如果电脑 CPU 占用很高、画面卡顿，应优先降低 FPS 或分辨率。

## 七、启动 MediaMTX RTSP 服务

### 7.1 修改 RTSP 端口并固定使用 TCP

1. 打开 `C:\CameraRTSP`；
2. 右键 `mediamtx.yml`，选择“打开方式 → 记事本”；
3. 按 `Ctrl+F` 搜索 `rtspTransports:`；
4. 将该行修改为：

```yaml
rtspTransports: [tcp]
```

5. 再按 `Ctrl+F` 搜索 `rtspAddress:`；
6. 如果要使用示例端口 `8556`，将该行修改为：

```yaml
rtspAddress: :8556
```

7. 按 `Ctrl+S` 保存并关闭记事本。

注意：只修改准确叫做 `rtspAddress` 的项目，不要误改 `rtspsAddress`、`rtmpAddress`、`hlsAddress` 等相似项目。

如果决定使用其他 RTSP 端口，例如 `8554`，则这里和最终拉流地址中的端口必须同时改成 `8554`。

不需要在 `mediamtx.yml` 中另外填写 `camera` 路径。OBS 第一次向 `/camera` 发布时，MediaMTX 会自动创建该路径。

### 7.2 运行 MediaMTX

1. 双击 `C:\CameraRTSP\mediamtx.exe`；
2. 会出现一个黑色命令窗口，保持该窗口打开；
3. 第一次运行时，Windows 防火墙可能弹出提示：
   - 勾选“专用网络”；
   - 不必勾选“公用网络”；
   - 点击“允许访问”；
4. 窗口中没有红色报错，并出现 RTSP listener/监听端口相关信息，就表示服务已经启动。

不要关闭这个黑色窗口。关闭后，其他设备就无法拉流。

如果双击后窗口一闪而过，通常是配置文件格式错误或端口已被占用。先撤销刚才的修改，重新严格按本节两行内容修改。

## 八、让 OBS 开始发布画面

MediaMTX 官方推荐 OBS 使用本机 RTMP 输入，再由 MediaMTX 对局域网提供 RTSP。这样操作最少，另一台设备最终拉取的仍然是标准 RTSP 地址。

1. 回到 OBS，点击右下角“设置”；
2. 点击左侧“推流”；
3. 按下面填写：

| 选项 | 填写内容 |
|---|---|
| 服务 | `自定义...` 或 `Custom...` |
| 服务器 | `rtmp://127.0.0.1/camera` |
| 串流密钥/推流码 | 留空 |
| 使用身份验证 | 不勾选 |

4. 点击“应用”，再点击“确定”；
5. 确认 OBS 预览中仍有摄像头画面；
6. 点击 OBS 右下角“开始推流”；
7. 按钮变成“停止推流”后等待 5 秒；
8. 查看 MediaMTX 黑色窗口，应出现含有 `camera` 和 `publishing` 的信息。

这里服务器地址使用 `127.0.0.1` 是正确的，因为 OBS 和 MediaMTX 在同一台电脑上。**不要**把另一台拉流设备的 IP 填到 OBS 的服务器地址中。

如果想将路径从 `camera` 改成 `test01`：

- OBS 服务器地址改为 `rtmp://127.0.0.1/test01`；
- 最终 RTSP 地址也改为 `rtsp://推流电脑IP:8556/test01`。

## 九、找到推流电脑的真实局域网 IP

Windows 11 可按以下方式查看：

1. 打开“设置”；
2. 点击“网络和 Internet”；
3. 点击当前正在使用的“以太网”或“Wi-Fi”；
4. 找到“IPv4 地址”；
5. 记录类似 `192.168.112.101` 的地址。

也可以按 `Win+R`，输入 `cmd` 并回车，然后输入 `ipconfig`，在当前正在使用的网卡下查找“IPv4 地址”。不要使用：

- `127.0.0.1`；
- `169.254.x.x`；
- 未连接网卡、虚拟机、VPN、蓝牙网卡的地址；
- “默认网关”地址。

假设查到的真实 IPv4 是 `192.168.112.101`，本教程的最终地址就是：

```text
rtsp://192.168.112.101:8556/camera
```

如果电脑断开网络、换路由器或使用自动分配 IP，该地址可能变化。每次正式测试前都应重新确认。

## 十、先在推流电脑本机验证

1. 保持 MediaMTX 黑色窗口运行；
2. 保持 OBS 正在推流；
3. 打开 VLC；
4. 点击“媒体 → 打开网络串流”；
5. 输入：

```text
rtsp://127.0.0.1:8556/camera
```

6. 点击“播放”；
7. 能看到摄像头画面，说明“摄像头 → OBS → MediaMTX”已经正常。

本机测试必须使用 `127.0.0.1`。如果本机 VLC 都看不到画面，先不要测试另一台设备。

## 十一、在另一台设备上拉流验证

### 11.1 使用另一台 Windows 电脑的 VLC

1. 确认两台电脑连接同一个路由器或交换机；
2. 在另一台电脑打开 VLC；
3. 点击“媒体 → 打开网络串流”；
4. 输入推流电脑的真实地址，例如：

```text
rtsp://192.168.112.101:8556/camera
```

5. 点击“播放”；
6. 能看到实时画面即表示跨设备 RTSP 拉流正常。

### 11.2 使用甲方自己的系统

将同一个 RTSP 地址完整填写到系统的“视频源”“摄像头地址”或“RTSP URL”输入框中：

```text
rtsp://192.168.112.101:8556/camera
```

如果系统可选择 RTSP 传输方式，优先选择 `TCP`。

### 11.3 成功时应同时满足

- OBS 中能看到连续摄像头画面；
- OBS 右下角按钮显示“停止推流”，说明当前正在推流；
- MediaMTX 窗口中出现 `camera` 和 `publishing`；
- 拉流设备连接时，MediaMTX 窗口出现新的 `reading`/reader 信息；
- 另一台设备能看到实时画面；
- 遮挡镜头或移动物体时，另一台设备画面同步变化。

仅仅“VLC 没有报错”不算完成，必须实际看到会变化的摄像头画面。

## 十二、建议的逐级测试方法

不要同时修改多个设置。按以下顺序逐级测试，每一级稳定运行 3～5 分钟后再继续：

1. `1920x1080@30`，最终 H.264，`6000 Kbps`；
2. 保持 1080p30，只调整曝光和增益；
3. `1920x1080@60`，最终 H.264，`8000 Kbps`；
4. 如业务确实需要，再测试 `1280x720@120`；
5. 最后再测试 MJPEG 采集格式、不同码率或 4K。

每次测试建议记录：

| 记录项 | 示例 |
|---|---|
| 摄像头采集格式 | H264 或 MJPEG |
| 摄像头分辨率/FPS | 1920x1080@30 |
| OBS 输出分辨率/FPS | 1920x1080@30 |
| OBS 最终编码器 | NVIDIA NVENC H.264 / x264 等 |
| 码率 | 6000 Kbps |
| RTSP 地址 | rtsp://192.168.112.101:8556/camera |
| 曝光/增益 | 截图记录驱动窗口中的实际值 |
| 测试结果 | VLC 正常、业务系统正常、是否卡顿 |

## 十三、停止推流的正确顺序

1. 在 OBS 中点击“停止推流”；
2. 等待按钮恢复为“开始推流”；
3. 关闭 OBS；
4. 最后关闭 MediaMTX 黑色窗口；
5. 不再使用摄像头时再拔掉 USB 线。

下次使用时依次执行：连接摄像头 → 启动 MediaMTX → 启动 OBS → 检查参数 → 点击“开始推流”。

## 十四、常见问题排查

### 14.1 OBS 找不到摄像头

- 确认 USB 线不是只能充电、不能传数据的线；
- 换一个 USB 3.x 接口；
- 关闭 Windows“相机”、会议软件和浏览器；
- 检查 Windows 相机隐私权限；
- 打开“设备管理器 → 相机”，确认没有黄色感叹号；
- 拔插摄像头后重启 OBS。

### 14.2 OBS 有摄像头名称，但画面是黑色

- 将“分辨率/FPS 类型”改回“设备默认”；
- 使用 `1920x1080@30`；
- 在 `H264` 和 `MJPEG/MJPG` 之间切换；
- 关闭其他摄像头软件；
- 在来源属性中点击“停用”，等待 2 秒后再点“激活”。

### 14.3 点击“开始推流”后提示无法连接服务器

- 确认 `mediamtx.exe` 黑色窗口仍然开着；
- OBS 服务器地址应是 `rtmp://127.0.0.1/camera`；
- 串流密钥必须留空；
- 确认没有修改 `rtmpAddress`；
- 关闭后重新启动 MediaMTX，再点一次“开始推流”。

### 14.4 本机 VLC 也无法播放

- 先确认 OBS 正在推流，而不只是显示预览；
- 本机地址必须是 `rtsp://127.0.0.1:8556/camera`；
- 确认 MediaMTX 配置中的端口与 VLC 地址完全一致；
- 确认 OBS 和拉流地址的路径都为 `camera`；
- 查看 MediaMTX 窗口中是否出现红色错误。

### 14.5 本机能播放，另一台设备不能播放

这通常不是摄像头问题，而是局域网或防火墙问题：

- 确认另一台设备使用的是推流电脑真实 IPv4，不是 `127.0.0.1`；
- 确认两台设备在同一局域网，且没有连接访客 Wi-Fi；
- 在推流电脑的 Windows 防火墙中允许 `mediamtx.exe` 通过专用网络；
- 如果单位网络启用了“客户端隔离/AP 隔离”，联系网络管理员关闭隔离或换普通路由器测试；
- 临时退出 VPN 后重试；
- 用另一台设备先测试能否访问推流电脑，再排查业务系统。

不建议把 Windows 防火墙整体关闭。只允许 `mediamtx.exe` 或 RTSP TCP 端口即可。

### 14.6 能连接，但画面卡顿、花屏或延迟很大

- 拉流端选择 RTSP over TCP；
- 推流电脑优先使用网线；
- 将 1080p60 改为 1080p30；
- 将码率从 8000 降到 6000 或 4000 Kbps；
- OBS 编码器优先选择硬件 H.264；
- 打开 OBS“查看 → 统计信息”，观察是否有丢帧或编码延迟；
- 先用 VLC 比较。如果 VLC 正常而业务系统异常，重点排查业务系统的 RTSP/H.264 解码能力。

### 14.7 画面太暗、噪点多或运动拖影

- 拖影严重：减小曝光时间；
- 太暗但不拖影：增加现场照明，再少量增加增益；
- 噪点多：降低增益；
- 灯光横纹闪烁：电源频率选择 `50 Hz`；
- 参数不断自动变化：取消曝光、白平衡或增益的“自动”选项。

### 14.8 1080p60 或 720p120 选不到/跑不稳

- 确认摄像头接在 USB 3.x 接口而不是低速 Hub；
- 优先选择摄像头的 H264 或 MJPEG/MJPG 采集格式；
- 确认 OBS“设置 → 视频”中的输出 FPS 也已相应修改；
- 如果 OBS 的“常用 FPS 值”没有 120，可将 FPS 类型改为“整数 FPS 值”并输入 `120`；
- 高帧率对 USB、电脑编码器和网络要求都更高，不能稳定时先回到 1080p30 完成系统功能验证。
