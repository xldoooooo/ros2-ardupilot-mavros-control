## 具体要求



当前甲方的某些命令只对应我们的一个单独的命令，但实际上他们设想的是对应一个动作系列。所以首先要实现组合功能的映射：

1. 将甲方的“执行巡检任务“，映射成：
   + 起飞（到地面站指定的起飞高度）
   + 起飞完成后，执行航点
   + 所有航点执行完毕后，在最后一个航点处降落
2. 将甲方的”一键返航“，映射成：（以当前所选中的控制组合）执行航点（0,0,<起飞高度>），稳定后降落；然后在源码标记一个TODO
3. 巡检任务下发和紧急停机则保持当前映射不变
4. 低电量自动返航，映射成：执行一键返航相同的行为；然后在源码标记一个TODO
5. 当”无人机状态异常“时，执行一键返航相同的行为；然后在源码标记一个TODO



然后对照甲方的时序交互图，检查我们现在的已经实现的功能是否与对方的要求有所不同，并进行完善或修改

1. 实现待机状态的发送，具体来说是：

   1. 在飞机解锁后（等价条件是能够在地面站点击飞行）的时候，若满足自身位于机库的判定，则发送一次待机状态
   2. 在收到巡检任务/执行巡检任务/巡检完所有航点的时候，都不发送待机状态
   3. 在巡检任务执行完毕并降落后，延时1分钟（此参数可能后面会变化），然后若满足自身位于机库的判定，则发送待机状态
   4. 一键返航/低电量自动返航 -> 降落后，若满足自身位于机库的判定，发送待机状态
   5. 紧急停机 -> 降落后，不发送待机状态，直到满足自身位于机库的判定，此时发送一次待机状态
   6. 无人机状态异常 -> 返航降落后，若满足自身位于机库的判定，清除状态异常，并发送待机状态（在此处代码中标记一个TODO）

   + 自身位于机库的判定：当前只需判断自己是否位于原点附近，若三轴位置基本都靠近原点（X, Y, Z 绝对值同时小于某个阈值。阈值是能修改的参数，默认X和Y的阈值是1.0米，Z的阈值是0.5米），则就认为自己在机库。这里在代码中标记一个TODO。后续可能会与机库上的设备进行联动，从而实现更准确的判定方式。

2. 修改“任务执行完毕”的发送逻辑，只有在执行完毕所有航点巡检任务的时候才会发送。其他情况一律不发送







## 航点入点判断逻辑修改

当前入点判断，若入点速度太大，会认为执行失败，然后好像就一直停留在原地不继续执行了。

你要修改成：

若按当前逻辑进行的入点判定失败，则进行一次入点尝试失败计数，然后继续执行当前航点任务（相当于让飞机继续入当前这个点，在这个航点自己稳定下来）；每隔1秒重新判定一次，若间隔1秒后仍然入点失败，则失败计数+1。入点成功后，失败计数清零。若失败计数大于等于10, 则将无人机标记为“无人机状态异常“，并执行相关逻辑。

（应该有多种情况能判断无人机状态异常，目前我们先只实现这一种判定方法）
