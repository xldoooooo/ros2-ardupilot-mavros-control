# 飞控热重启与热重联



## 入口1：地面站

在地面站主GUI右上角，“退出地面站”按钮左侧，加一个按钮”重启机载飞控“，按钮风格与”退出地面站“一致，点击后也会弹出二次警告提示框

当且仅当如下条件满足时，此按钮允许点击，否则处于禁用状态（灰色，不可点击）

1. 已连接实机
2. 飞机已经降落在地面上，处于待机状态，无任何正在执行的任务；飞控未解锁



点击后的效果：

1. 若飞控不存在，则报告异常

2. 若onboard control异常，则报告异常

3. 若onboard control机载服务运行正常，且能检测到飞控，则通过mavros向飞控发送重启指令;

   重启的效果，应当等效于Mission Planner里面点击reboot重启 即可，不需要达到断电重启级别



可以确定，以下条件始终满足：

1. 机载计算机在线
2. 飞控与机载计算机始终物理连接，且连接方式不变



不需要考虑：

1. USB 串口设备完全消失后重新枚举
2. 自动恢复此前任务/控制状态



## 入口2：机载脚本

在ros2-ardupilot-mavros-control根目录下创建一个reboot_fcu.sh 脚本作为重启流程的简易入口，方便我在没有地面站的时候直接通过机载计算机重启飞控

它只需作为薄入口，不要用sh脚本实现全部重启功能

+ 若在飞机上执行它，调用onboardcontrol相关的飞控重启逻辑，
+ 若在地面站所在计算机上直接执行它，则简单判断后直接拒绝执行即可；即 只允许在飞机上用脚本重启，地面站必须通过GUI按钮重启



### 即：

```
地面站 GUI ─┐
           ├─ 调用 onboard_control “重启飞控”
机载端脚本 ─┘
```



## 注意事项

1. 重启前后飞控都要处于锁定状态
2. 在onboardcontrol正常运行的情况下，如果飞控单独重启，onboardcontrol应当能自动重连，恢复完整控制链路
3. 需要进行可靠判断以及日志输出（输出到地面站主GUI日志框
   + 飞控重启成功
   + 控制链路成功恢复
4. 尽量减少此功能与现有代码的不必要耦合，控制代码复杂度；保证在不进行热重启操作时的逻辑与本次任务修改前一致。做最小化修改。
