# 避障算法集成

我们前几次任务中，移植了一个避障算法到ros2jazzy. 现在希望利用这个避障算法，集成到飞机上，从而实现之前一直是占位符的地面站UI中的两个避障策略。希望集成后不能影响原有的功能，具有合理的独立性



## 具体要求

1. 不影响原有功能，在地面站UI选择的模式是直线飞行时，不会受到避障功能的任何影响
2. 遇障悬停策略的行为是：如果发现飞机当前位置与目标点的直线连线上存在会碰到障碍物，则悬停在原地等待；等待时间内若障碍物消失则继续飞行任务；等待超时则原地降落
3. 自主避障策略的行为是：按照避障算法规划出来的轨迹进行飞行任务；规划失败/无路可走时，悬停在原地等待；等待时间内若又获取到了可行的路线，则继续飞行任务；等待超时则原地降落

避障算法的路径规划，应当以正在飞往的下一个航点为终点，不应该直接规划全部航点的轨迹。

避障算法应当运行在飞机上；地面站需要在当前rviz可视化中，把规划出来的轨迹可视化集成进去；并评估点云图数据能否在局域网中传到地面站，如果可以，也可以一并在地面站的rviz中可视化。如果带宽不足或对机载计算机造成计算压力，则不强行可视化。



我设想的是。保持原有的PD+DOB轨迹跟踪控制算法尽量不变化，减少修改量，尽量复用原来的控制算法。

我建议首版直接执行规划器已有的带时间轨迹，复用现有 PD+DOB

`/kino_path`：一系列位置点及时间戳，没有速度、加速度字段，可用于RViz 显示

`/plan_result.trajectory`一系列带相对时间的 **位置、速度、加速度** 用途：采样带时间的轨迹数据

`/plan_result.segments`每段的持续时间和 XYZ 多项式系数  用途：可以计算任意时刻的参考



## 注意事项

+ 几种策略的进入航点的判定入口和方法应该是同一套；几种策略在巡检任务中 进入航点后都会有相同的拍照行为；其余的相关行为也应当保持一致性

+ 我希望飞机在跟踪轨迹规划器给出的参考轨迹的时候，运动比较平稳。水平最大速度1m/s，其他各参数也应参考当前航点任务的（梯形轨迹+轨迹跟踪PDDOB）设置

+ 禁止飞行途中变换避障策略，只有在飞机起飞之前可以选择。一旦起飞后不允许中途再次选择，直接将地面站按钮禁用（当前行为就是这个），因此也不需要考虑飞行半路如何变换策略

+ 可在SITL中充分测试

+ 飞机 refresh已连接，当前odin的设置已经开启了点云图

  按需进入飞机调试。**（注意安全，可启动飞机odin, 启动机载服务等进行调试，但不要起飞或解锁，飞机上的操作不要交给子代理）**



+ 当前odin模块是仰角约20度看向前上方安装的，与之前的水平安装不同。**初步分析不会对避障产生影响**，**先不要根据odin仰角修改适配本项目当前的odin-tag校准相关代码以及其他与odin角度/外参相关的代码。**本次完成避障功能后，会在完全不使用odin-tag校准功能的情况下进行测试，先保证本次避障功能测试的可行。后续若有需要补齐的针对这个odin仰角的适配，在任务执行报告中特别标注。



## 可参考的意见

悬停-恢复 这个比较困难。可以考虑将此任务分两个大的阶段实现：

1. 阶段一，悬停之后永久终止，可直接复用当前悬停逻辑，不考虑后续恢复任务。**优先确保基本的避障，路径规划，跟踪飞行行为是可用的。**
2. 阶段二，加入恢复逻辑，建议是在避障任务中使用一种 与当前地面站UI上的悬停所不同的悬停策略





## 任务执行方法

+ 难度不高的独立任务，根据实际情况，合理选择并发布 6.1-sol light/medium/high 子代理并行执行
+ 多次尝试仍失败困难任务，或数学关系特别复杂 执行后对正确性把握不高的任务，发布一个6-astra-high 子代理协助研究
+ 相互无关的要交给子代理的任务，应当新发布子代理去执行，而不要一直沿用旧的。
