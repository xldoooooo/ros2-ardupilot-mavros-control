的难度，工作量，以及风险-回报。



## 边界与注意事项

1. 只需要path searching和 path plan 两部分。其余的不需要移植和集成
2. 障碍物点云数据由Odin直接给出。具体参考当前项目的odin. 飞机`new`已上线，可按需检查



## 预期效果

1. 如果移植可行，我希望创建独立仓库，存放此A*避障的ROS2版本（只path_planning 和path_searching），从而形成可复用的  不强制绑定本项目的算法

2. 如果集成可行，则我另外还希望如集成到本项目，尽量保持独立，不要与地面站或机载服务现有代码耦合；

3. 算法应当运行在飞机上

4. 集成后，具体行为是：

   + 在地面站“避障策略” 中 选择“自动避障”时：

     执行航点任务时，以自身位置为算法出发点，以终点（下一个航点）为算法期望目标点，实时（10Hz左右）调用算法进行避障路径规划；将算法生成的插值路径直接作为飞机的期望飞行路径，不需要再使用我们的插值轨迹生成；

     如果避障策略执行到某个阶段时，因为目标点不可达或其他任意原因导致规划失败，则悬停在当前位置并进行一定持续时间的等待；等待超时后，终止航点任务并原地降落

     

   + 在地面站“避障策略”中选择“遇到障碍悬停“时：

     执行航点任务时，以自身位置为算法出发点，以终点（下一个航点）为算法期望目标点，实时（10Hz左右）调用算法进行避障路径规划；一旦以某种方式可靠判断到自身位置到期望点之间存在障碍物，则悬停在当前位置并进行一定持续时间的等待；等待超时后，终止航点任务并原地降落
