## 实现内容

### 1. 命令 03：完整巡检时序

- 收到 03 后，地面站捕获当时 GUI 中的起飞高度与航点列表，建立单一时序上下文。
- 仅在可靠的 `CommandResult` 终态与当前 ticket 匹配时推进阶段，依次执行：
  1. 起飞到 GUI 设置高度；
  2. 逐个执行捕获的巡检航点；
  3. 全部航点可靠完成后在最后一个航点执行 LAND。
- 航点进度 09 只与巡检航点完成对应；全部巡检航点成功时只发送一次 08。
- 起飞、返航和降落阶段不产生伪造的 09/08；旧 ticket 的迟到结果不会推进新任务。

### 2. 命令 05、低电量与异常返航

- 05 在接收时捕获 GUI 当前选择的速度、容差和稳定时长组合，并以 `(0, 0, 起飞高度)` 覆盖为单点返航任务。
- 到达返航点并满足稳定判定后自动 LAND；返航过程不发送 09/08。
- 低电量 0C 与无人机异常使用同一条返航时序；低电量触发在 WebSocket 临时断线时仍能在本地继续进入安全返航流程。
- 异常返航落地并严格进入机库阈值后，地面站先可靠发送命令 6 清除机载异常，再解除状态 01 锁定。
- 紧急降落继续映射为 LAND；若落点不在机库范围内，状态 01 保持锁定。

### 3. 状态 01 与 08 的发送规则

状态 01 现在是“可再次起飞且已入库”的边沿消息，而不是一般任务完成消息：

| 场景 | 状态 01 行为 |
|---|---|
| 初始就绪、可起飞且在机库内 | 发送一次 |
| 任务下发、起飞、巡检、降落过程中 | 不发送 |
| 巡检成功并降落 | 默认等待 60 秒，且位置进入机库后发送一次 |
| 05 或低电量返航并降落 | 进入机库后发送一次 |
| 紧急降落在机库外 | 不发送，直至之后进入机库 |
| 异常返航并降落 | 入库并可靠清除异常后发送一次 |

- 入库判断采用严格小于：`|X| < 1.0 m`、`|Y| < 1.0 m`、`|Z| < 0.5 m`。
- X/Y/Z 阈值和巡检后等待时间可由 `UPSTREAM_HANGAR_*` 与 `UPSTREAM_INSPECTION_STANDBY_DELAY_SECONDS` 配置。
- 08 只在全部巡检航点可靠成功时发送一次，所有返航路径均不发送。

### 4. 航点入点失败与异常状态

- 新增独立、可单元测试的 `WaypointArrivalTracker`。
- 未进入位置候选区时属于正常接近，不计失败。
- 首次进入候选区但速度不满足时立即计 1 次；保持当前航点并按默认 1 秒周期重判、递增。
- 达到稳定入点条件后完成该航点并将计数清零。
- 默认累计到 10 次后设置持久的 `vehicle_abnormal` 与原因；地面站据此自动启动异常返航。
- `ControlStatus.msg` 新增当前失败数、异常标志与异常原因；`FlightCommand.srv` 新增异常清除命令 6。
- 线级接口升级为 3.1，`guided_interfaces` 和 `onboard_control` 包版本升级为 3.1.0，部署文档与 smoke 期望同步更新。

### 5. 上位机面板

- URL 和无人机编号在有效配置时原子保存到用户 JSON 配置；新进程按“显式参数 > 环境变量 > 用户配置 > 默认值”恢复。
- 原始帧区域新增轻量查找框与“查找下一个”，支持循环查找。
- 01、03、05、08 与 JSON 示例说明已同步当前真实行为。
- 关闭面板会保存有效配置，但不会改变后台连接状态。
