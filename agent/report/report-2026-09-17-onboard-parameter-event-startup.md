# 通过必要参数事件进一步缩短机载启动

本报告记录在上一轮离线启动/校时修复基础上的进一步优化。生产改动仅涉及机载端参数接收与校验，
没有修改 MAVROS、飞控参数、串口设置、READY 条件或 Linux 自启顺序。

## 原因与方案

new 安装的 MAVROS 2.14 参数插件在收到每个 PARAM_VALUE 时立即发布 /mavros/param/event，
但整表 pull 服务等待期间，同组缓存读取服务可能被阻塞。因此必要参数已到齐不等于原服务读取
已经返回。本次改动前真实重启：MOT_THST_HOVER(index=500) 在启动后约 19.13 秒到达，
GUID_OPTIONS(index=1122) 约 32.22 秒到达，机载校验仍到 39.16 秒才通过，READY 为 39.54 秒。

现在机载端用可靠、volatile 的订阅接收上述两个必要参数：

- 只处理飞控已连接时的新事件，不取历史 transient 缓存；断线清空已收的两个参数。
- 两值齐全时复用原来的类型、GUID_OPTIONS bit 3 和 MOT_THST_HOVER 有效范围校验。
  不以收到任意事件、拉表 ACK 或进程存活替代校验。
- 显式错误类型、错误 bit 或非法浮点值不能就绪；新参数事件能撤销已经验证的错误状态。
- 同一套校验函数也供原缓存服务调用。保留缓存服务回退和通过后每 5 秒复核；较旧的在途
  缓存读取若跨过新事件或断线，则忽略其结果，避免覆盖较新状态。
- 完整参数表仍后台同步；不新增 MAVLink 写命令，不另开串口，不增加软件依赖。

## 实测

按 systemd 单调 journal 计时，从新服务开始执行到打印 READY，不含 restart 停止旧进程的时间。

| 阶段 | 本轮改动前 | 新版第一轮 | 新版第二轮 |
| --- | ---: | ---: | ---: |
| 主动拉参数 | 9.12 s | 10.13 s | 8.93 s |
| 必要参数校验 | 39.16 s | 33.36 s | 32.06 s |
| READY | 39.54 s | 33.76 s | 32.45 s |
| 整表同步完成 | 39.51 s | 40.35 s | 39.45 s |

新版第一轮 GUID_OPTIONS 事件 header 为 epoch 1789582950.115370416，机载校验日志为
1789582950.115757107，相隔约 0.39 ms。READY 在校验后约 0.40 秒打印，早于整表完成约 6.60 秒，
直接验证事件路径消除了多余的整表等待。不会声称剩余原生参数传输也已加速。

SITL 完整生产初始化成功：必要参数约 7.06 秒验证，完整 READY 44.20 秒；仿真仍受 EKF/GPS
冷启动限制，没有缩短到实机同样时间。全程不解锁、不起飞，4 个受管进程清理完成，无残留。

## 限制与记录

并未改善，当前 READY 只解除与无关参数的等待耦合。若继续大幅提速，需要单独验证按名称优先读取，
不能把本次事件优化解释为已经实现了该能力。

离线启动能力及上一轮相对时间 READY 超时保留。未重启 Linux、制造系统校时或实飞；真实离线
冷启动后的 NTP 现场复验仍未覆盖。refresh 与独立 USB Jetson 尚未同步此改动，MEMORY 标记待同步。
