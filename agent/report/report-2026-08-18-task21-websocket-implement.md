## 1. 结论

本次采用“独立通讯插件 + 地面站薄适配”的结构：WebSocket 生命周期、JAR 主题信封、协议校验、命令映射、状态投影和原始报文日志集中放入独立的 `ground_station_core/upstream/`；地面站主窗口只负责把已经校验和转换的高层动作交给原有按钮路径，并把原有权威快照与可靠命令结果提供给状态投影器。

实际调用链为：

```text
上位机 JAR 主题服务
  -> 独立 WebSocket 线程（订阅、校验、确认、映射）
  -> Qt 主线程信号
  -> 地面站既有起飞/降落/航点入口
  -> GroundStationRosController
  -> 既有机载高层服务
```

没有修改 `src/guided_interfaces/`、`src/onboard_control/`、`src/guided_sim/` 或任何控制算法。现有机载接口已经能够表达起飞、降落和原子替换航点任务，命令 05 和 07 可由这些既有能力组合完成，因此没有必要在机载端建立另一套上位机专用控制通道。上位机连接关闭、崩溃或依赖缺失时，原地面站及原机载链路保持原行为。

`video-service/` 未作任何修改。

## 3. 架构与隔离设计

### 3.1 独立生命周期

- 插件随地面站窗口构造而启动，默认按环境变量尝试连接。
- WebSocket 使用专用 daemon 线程和独立 asyncio 事件循环，不在 Qt 主线程执行网络等待。
- 通讯面板可单独执行“连接”“断开”“重启连接”。
- 关闭通讯面板不关闭连接，关闭 WebSocket 连接不清理 ROS、仿真、实机会话或机载租约。
- 地面站退出时限时停止插件；即使插件停止异常，仍继续执行原地面站清理。
- `websockets` 采用延迟导入。依赖缺失时只把插件置为“依赖缺失”，原地面站仍可正常启动、操作和退出。
- URL 或无人机编号配置非法时回退为断开状态，不阻断主窗口启动。

### 3.2 传输层

- 对接任务 19 已验证的 JAR 原生协议：`SYSTEM` 首帧、`SUBSCRIBE/SUB_ACK`、`PUBLISH/BROADCAST`。
- 控制主题：`drone/{clientNo}/command`。
- 状态主题：`drone/{clientNo}/status`。
- 每个 WebSocket 会话只有一个 reader 和一个 writer，避免并发 `recv/send`。
- 发送队列上限为 256，满时丢弃最旧消息；每次会话边界清空旧消息，不在重连后发送过期业务状态。
- 自动重连间隔为 3 秒；重复连接错误的人类日志按原因限速，面板状态仍实时变化。
- 会话重启会完整取消并等待旧 reader/writer，防止旧 writer 抢走新会话的首条确认消息。

### 3.3 日志隔离

- 原始 RX/TX 文本帧只写入独立 `RawFrameJournal`，最多保留 2,000 帧。
- 通讯面板按序号增量显示精确原始文本，并支持只清除原始报文。
- 地面站主日志只记录“收到、拒绝、连接、状态上报”等供维护者阅读的语义信息，不复制原始 JSON 信封。

## 4. 命令映射和执行门控

映射关系只定义在 `ground_station_core/upstream/mapping.py`，WebSocket 核心和 Qt 面板均直接使用同一份映射表。

| 命令 | 映射后的动作 | 当前实现 |
|---|---|---|
| 01 | 起飞 | 复用地面站既有起飞入口；仿真直接排队，实机仍保留本地高风险人工确认 |
| 02 | 下发巡检任务 | 先完整校验全部航点，再一次性原子替换 GUI 航点列表；成功后发送状态 02 |
| 03 | 执行巡检任务 | 复用“发送并执行航点”；未起飞、无航点、任务运行中或控制链未就绪时拒绝 |
| 05 | 一键返航 | 停止/覆盖当前航点任务，使用 GUI 当前策略、参考生成器和跟踪控制器，执行 `(0, 0, 起飞高度)` 航点 |
| 06 | 降落 | 复用既有 LAND 入口和可靠命令 ticket |
| 07 | 紧急停机 | 映射为立即原地 LAND，不新增不存在的机载“停机”指令 |

具体边界：

- 只有当前活动会话为 `simulation` 或 `hardware` 时才可能执行命令；没有活动环境时明确拒绝。
- 仿真会话的所有上位机动作只进入隔离的 domain 231 仿真链路；实机会话才可能进入实机链路。
- 所有命令继续服从原地面站的 ROS 就绪、机载在线、端点冲突、控制权、位姿、推力语义和任务状态门控。
- 实机起飞、降落、返航和航点任务仍需地面站本地人工确认；上位机消息不能绕过项目的实机操作确认。
- 合法协议命令收到后先返回“接收确认”。如果随后不满足本地执行条件，GUI 和人类日志明确记录拒绝原因；协议没有定义负确认格式，因此不会伪造新字段。
- 命令 02 在校验完成前不会修改 GUI，避免部分成功、部分失败。
- 航点限制复用项目边界：数量上限、X/Y 水平范围、Z 为 `[0.1, 50] m`、有限数值、点号为不重复正整数。
- `forwardAngle` 按角度读取、归一化到 `[-180°, 180°)`，再转换为本地弧度偏航角。
- `cameraAngle` 和 `photoNo` 当前只做格式校验并忽略；首次处理命令 02 时写明日志，源码保留集中 TODO 扩展入口。
