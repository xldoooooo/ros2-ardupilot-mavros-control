## 实现

- 规划器仍在独立工作区运行，新增`PlanMotion`服务，使用请求中的实际FCU位置/世界速度和下一个
  业务航点，支持PLAN、CHECK_LINE及剩余多项式校验。生产`service_only=true`关闭旧目标定时搜索；
  `latest_observation`接收桥的完整观测地图，不重复按旧50帧累积/擦除地图。
- 主工程新增独立`avoidance_bridge`，不发布FCU命令或setpoint。0.1m体素持有占用与自由证据，
  首帧原点半径20m、最多300000格、每帧最多10000条离散射线、最多2Hz地图计算。未看见的区域
  始终unknown；只有新扫描射线穿过旧占用格且终点在后方，才移除占用，无TTL自动消障。
- 云/里程计schema、有限值、源时标前进、源时标匹配与接收年龄各自校验；重复不刷新年龄，时钟
  回退/坐标变更清图。容量饱和、空扫描、坏schema、断流或覆盖不足均拒绝执行。
- 无Tag基线读取extnav同session/revision最终样本与杆臂T：世界障碍加T进入map，请求p/goal减T，
  返回多项式只在常数项加T，速度不旋转。按extnav实际公式校验FCU中心，一致性≤0.25m；
  raw/FCU按接收时间≤0.1s配对，cloud/raw按源时标≤0.1s配对。未从一次姿态差推定世界外参。
- 控制器新增独立执行文件，直接按单调经过时间计算原多项式p/v/a，复用原PD+DOB，不重新平滑
  或裁剪参考。入口检查段数/总时长、C1、起终点、末速度及完整水平/垂直速度加速度包线；
  二次速度用Bezier凸包递归验证，线性加速度检查端点。实际起点p/v须在0.08m/0.08m/s容差内。
- 固定参考限制为水平1m/s、垂直0.2m/s、水平加速度0.35m/s²、垂直0.15m/s²，与当前梯形设置一致。
  低加速度搜索用`max_tau=1s`跨越0.1m hash格；不是降低距离或动力学标准。
- 独立等待保持任务、1-based业务航点和起飞配置锁，停止入点/拍照，使用实际位置零速参考制动。
  连续0.4s新鲜有效结果后恢复；等待15s包含制动，失败结果不延期。曲线断流、会话/坐标变化、
  校验失败或跟踪偏差过大进入等待。超时失败当前任务并锁存LAND，负ACK/服务缺失/挂起请求
  按有界时序重试；只有实际LAND停止重试，实际解除武装才解除锁存。普通悬停/操纵/新航点不能抢回任务。
- 共用原实际入点与拍照路径，暂停不触发照片，恢复不改变业务索引。直线分支沿用原参考算法，
  起飞和航点均不依赖规划组件ready；两种避障策略在组件不ready时拒绝接单。
- 起飞前锁定策略、生成器与跟踪器，起飞失败解锁；断线重连按机载锁状态恢复GUI禁用项。
  自主避障要求轨迹PD+DOB，GUI显示实际规划参考，无静默直线回退。
- 控制会话、任务revision、航点、单调请求id、桥/规划会话、坐标revision关联响应，旧任务/旧航点
  响应不接受。结果0.8s内有效。地图/服务消费竞争在同一原请求期限内内部重验最新图，只有最新图
  成功才能回成功，消费延迟不续期；真失败/unknown/期限耗尽仍进入等待。
- RViz显示控制器已经接受的当前Path；取消/失效即清除，地面接收超时0.8s清除，状态订阅使用
  与机载匹配的BEST_EFFORT。可选云预览默认关闭，最多10000 XYZ点×2Hz，仅有订阅时生成。
- 飞行协议及guided_interfaces/onboard_control/guided_sim升3.4/3.4.0；视频仍独立3.2。
  更新了正式飞控重启客户端和部署smoke的版本门控，避免升级后破坏原功能。

保留用户指定的0.45m质心距离规则，没有体素/采样补偿半径，严格小于阈值才拒绝。
独立库连续三次曲线碰撞检查改为距离平方导数实根与端点的解析最小值，修复Task37原语两端之间

### 真实ArduPilot SITL

固定domain231/LOCALHOST，只连接标准本地SITL/MAVROS。场景使用有限前向FOV ±55°/±35°，
1°射线，取盒子/圆柱首个交点，圆柱遮挡后方，不注入隐藏空闲格。圆柱半径0.18m；盒子范围
相对地面FCU原点为x[-2.5,6]、y[-2.5,2.5]、z[-0.25,3.5]m。先真实扫描未来区域，再插入/移走
障碍；保持生产300000格容量与全部飞行/净空参数。

| 场景 | 实际结果 |
| --- | --- |
| straight，规划组件未启动 | 起飞→3m业务航点→拍照1次→LAND并确认disarm |
| hover_recover，途中圆柱受阻/移走 | 受阻漂移0.0565m、0照片；约0.904s恢复；最终照片1次并降落 |
| avoid，途中圆柱绕行 | 最小实际表面净空0.5249m、横向偏移1.1385m；照片1次并降落 |
| avoid_recover，目标被圆柱占用/移走 | 受阻漂移0.0560m、0照片；约1.109s恢复；最终照片1次并降落 |
| timeout，保持圆柱阻挡 | 受阻漂移0.0576m、0照片；15s等待超时，实际LAND/disarm确认 |
| fault_cancel，等待中用户悬停 | 受阻漂移0.0549m、0照片；移走后不恢复，任务/航点已清除；正常降落 |

绕行采样最高参考水平速度0.7750m/s、实际0.8072m/s；自主恢复分别0.8795/0.9080m/s。

## 失败记录与修正

   初次直线成功后清理LAND重复请求曾被已disarm状态拒绝，后续脚本等待终态传播，未据此伪造飞行失败。

   增加真实CPP/DDS起飞成功/失败及配置更换覆盖。
3. 初次悬停恢复场景用z=0盒子地板，与地面FCU原点重合，射线穿出不合理盒子导致地图容量饱和。
   保留失败证据，按真实地面FCU位于地板上方设置有限盒子；未放宽300000格或unknown规则。
4. 首次真实自主绕行因map/service更新竞争反复刹停，最终停在不足0.45m可规划净空处NO_PATH，
   超时降落；不是绕行成功。修复为同一原期限内最新图内部验证，添加DDS旧图/新图失败/持续落后
   用例后，真实SITL绕行完成。未改搜索距离或放宽净空以制造成功。
5. 审查发现成功回调可能抢在control tick前清除已经到期的wait；回调也检查同一截止时间。
   审查发现LAND负ACK/暂时服务缺失后不重试；增加仅避障锁存路径的有界重试与实际模式确认。
6. refresh全量规划测试初次1个逻辑DDS用例失败（colcon显示2个failure含包装）：测试强制
   future cloud_stamp大于消费时当前now，只剩约0.14s窗口。改为成功结果cloud/odom均精确匹配
   投递pair，另加0.16s消费延迟覆盖，匹配/等待/年龄门槛不变；原生完整44/44复验通过。
7. 一次自主恢复初始化与Python suite同期运行时CPP收到SIGTERM(code -15)，尚未发送起飞。
   退出来源未确定，不归因为算法成功/失败；保留证据并在独占SITL运行时重测成功。所有测试
   最终分阶段完成，全局清理测试仅在仿真回收后执行。
