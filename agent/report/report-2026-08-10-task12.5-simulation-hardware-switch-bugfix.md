# 任务 12.5：仿真/实机切换 bug 修复简报

日期：2026-08-10
任务文件：`agent/task/12.5-bugfix.md`

## 结论

任务描述中的两个故障来自两个独立的生命周期错误，现均已修复：

1. “断开真机”原先只释放租约，不销毁 domain 0 ROS context。旧的 Jazzy DDS
   participant 一直留到下一次点击“本地仿真”才被销毁，因此真机 Humble 终端把端点撤销阶段的
   `sequence size exceeds remaining buffer` 集中显示在仿真启动时刻，造成仿真流量进入真机的假象。
2. `source_id` 在同一 GUI 进程中保持不变，但每次重建 ROS context 都把租约序号从 0 开始。
   真机端按 `source_id` 保存最大租约序号，所以仿真结束后重连会被正确拒绝为“重复或乱序”。

修复后，断开真机或终止仿真都会在该会话边界立即停止 ROS 客户端并销毁 context；租约序号则在
整个 `GroundStationRosController` 生命周期中统一单调递增。仿真继续固定使用 domain 231、
`LOCALHOST`，并移除可能指向真机的 `ROS_STATIC_PEERS` / `ROS_DISCOVERY_SERVER`。

## 修改内容

- `ground_station_core/environment.py`
  - `EnvironmentInitializer.cleanup()` 在释放租约、清理本机受管进程后立即调用
    `GroundStationRosController.stop()`。
  - 停止 ROS 失败会合入 `CleanupReport.errors`，不伪造清理成功。
  - 仿真子进程继续显式继承 domain 231 与 `LOCALHOST`，不依赖调用者终端环境。
- `ground_station_core/ros_controller.py`
  - 增加控制器级租约序号锁与计数器；acquire、heartbeat、release 共用同一跨 context 序列。
  - 仿真切换继续清除显式真机发现 peer/server，切回实机时恢复 GUI 启动时的原值。
- `tests/test_environment_communication.py`
  - 新增断开会话立即停止 DDS context 的回归。
- `tests/test_ros_controller.py`
  - 新增跨重建 context 的租约序号单调性回归。
  - 扩充 `LOCALHOST`/实机发现环境恢复断言。

## 失败试验与如实限制

- 曾实测 Fast DDS `fastdds.type_propagation=disabled`，不能消除 Humble 端反序列化告警。
- 曾在两端临时安装并实测 Cyclone DDS；高层状态可达，但 Humble 端改为出现
  `invalid data size / string data is not null-terminated`，因此没有采用。临时安装的 7 个软件包已在
  本机和真机逐项卸载，没有执行 `autoremove`。
- ROS 官方明确不保证 Humble 与 Jazzy 跨发行版通信。直接连接或销毁真机 domain 0 的 Jazzy
  participant 时，真机仍可能输出 Fast DDS 反序列化告警；本修复保证这些报文不会再被延迟到
  仿真启动阶段，并以抓包证明仿真 `LOCALHOST` 本身不向局域网出站。若后续要求连“真机连接/
  断开本身”也完全零告警，需要把实机薄客户端放入 Humble helper/container，或引入受支持的
  白名单网关；这属于跨发行版传输架构升级，不应冒充本次仿真隔离修复。
