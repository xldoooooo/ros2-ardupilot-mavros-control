# ROS2–ArduPilot 多设备部署

交付可核实的目标机状态：哪些源码和配置已更新，哪些产物已构建、进程已加载，哪些功能仍未验证。仅处理本次指定设备与功能范围。

## 确定目标和差异

- 读取适用的 AGENTS.md；本机 MEMORY 存在时只读目标设备、相关模块及漏同步项。未指定飞机时按项目约定连接 refresh，不可达即询问用户，不改连其他飞机。技能不扩大本次授权，实机解锁和起飞只能由用户操作。
- 核对源和目标的仓库根、主机/架构、飞机选择、Git 分支与 staged/unstaged/untracked 改动。Git HEAD 不能代表未提交源码、安装产物或正在运行的版本；稀疏检出还需核对实际存在的目录。
- 从 [配置索引](../../../config/README.md) 识别公共源码、逐机参数/标定、host/aircraft 本机选择、地图与媒体数据。同一仓库中的 `config/aircraft/` 也可能有现场修改，不能因其受 Git 跟踪就直接覆盖。
- 只比较本次影响文件和依赖；接口修改沿生产者/消费者追踪到机载、地面、独立 overlay。把实际兼容性要求与“该设备暂未更新”的记录分开，不把全部历史漏同步项自动纳入本次工作。

## 同步与原生构建

- 公共源码优先用现有 Git 工作流同步；需要交付未提交源码时，明确文件清单与源端状态，逐文件比较。先保存将被替换的唯一现场修改，不能使用整仓 reset/clean 或无差别 rsync 删除/覆盖。
- 仅在本次需要时改目标参数，保留其他逐机标定、地图、媒体、本机环境与用户修改。不要把开发机的 simulation 选择或另一架飞机的外参套到目标机。
- 不跨机复制 build/install 或架构相关二进制；按目标机实际 ROS、MAVROS、OpenCV 及 overlay 原生构建。使用全部可用 CPU/内存，不设低优先级；依赖沿现有安装入口补齐，不另建部署系统。
- 按任务读取入口，不通读所有部署文档：
  - 飞机：[机载部署](../../../src/onboard_control/deploy/ONBOARD_DEPLOYMENT.md)。核对脚本副作用；安装、构建、启用服务与启动服务是不同操作，`--install-only` 也可能构建和安装。
  - 地面站：[安装脚本](../../../scripts/ground/setup_ground_station.sh)及[测试入口](../../../tests/README.md)。局部升级不默认重装整个地面站。
  - 只有涉及相应模块时，读取 [Odin](../../../drivers/odin/README.md)、[extnav](../../../correction_service/extnav_patch/README.md)、[避障桥](../../../src/avoidance_bridge/README.md)、[FPGA](../../../fpga_avoidance/README.md) 或 [视频](../../../video_service/README.md)。
- 先明确本次是否需要停服/重启。在用户已授权的地面维护中可停止受影响服务，不必保持机载运行，也不默认恢复或启用开机自启。普通部署不得顺带改变导航模式、飞控参数或执行任务。

## 验证与交付

按 [部署验证](references/verification.md) 选择与改动相关的证据；接口变更必须覆盖消费端重建，纯参数变更通常只需回读与必要重启。优先复用 `tests/run.sh`，不在技能里复制测试映射。

交付时简述目标、变更范围、保留的现场差异及四种状态：源码已同步、产物已构建、运行已加载、功能已验证。没有启动的服务标为待加载，不能用旧进程或旧二进制通过代替新版本验收。

仅部署/同步默认在聊天交付；只有用户明确要求报告或本轮实质修改了项目交付的编程语言代码，才按[报告工作流](../project-maintenance/references/report-workflow.md)新增报告并更新索引。按实际变化维护受影响专题；MEMORY 仅维护目标机当前基线、其他设备仍缺的关联修改及未解决风险，不写部署流水。`agent/` 和 MEMORY 是本机资料，新检出缺失时依靠当前源码、配置与现场核验继续工作，不虚构历史状态。
