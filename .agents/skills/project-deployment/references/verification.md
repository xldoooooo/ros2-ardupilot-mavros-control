# 部署验证的证据选择

文件链接相对本文件；命令从仓库根目录运行。下列项目按影响选择，不是每次部署的全量清单。

| 本次改动 | 应取得的证据 | 不能替代它的结果 |
| --- | --- | --- |
| 公共源码同步 | 目标文件内容/校验和与本次源清单一致，现场差异仍保留 | 只比较 Git HEAD |
| ROS 消息、服务、C++ 或独立 overlay | 生产者与实际消费端均原生重建，包前缀及动态库来源正确 | 新消息源码搭配旧 install |
| 逐机 YAML、环境或标定 | 目标选择正确，实际读取路径及有效值与本次意图一致 | 只看开发机文件 |
| 服务入口或 unit | 已安装 unit 的 ExecStart、环境及工作目录指向预期路径 | 只修改仓库中的 unit 模板 |
| 正在运行的 C++ 服务 | 重启后的 PID/启动时间、可执行文件与相关库来源；需要区分版本时读 Build ID | 磁盘文件更新但进程仍映射旧库 |
| Python/GUI 修改 | 使用目标项目环境，受影响进程重新加载，定向回归通过 | 未重启的 GUI 或仅语法检查 |
| 媒体交付 | 在涉及的 HTTP/FTP/RTSP 路径实际读取、解码或比较文件 | API 健康或进程 active |

## 构建和功能范围

- [机载部署](../../../../src/onboard_control/deploy/ONBOARD_DEPLOYMENT.md)区分 build、verify、smoke 和安装。先核对当前脚本与接口定义，不在技能中固定版本号或输出阈值。
- [测试入口](../../../../tests/README.md)支持 `bash tests/run.sh --files <本次文件...> --list` 预览范围，再执行对应检查；并发改动存在时优先显式文件范围。新增依赖关系仍由测试入口维护，不能仅靠旧映射假定覆盖。
- 修改接口/C++ 后先构建再测试。底层测试使用的二进制必须属于本次构建；跳过项单列。只有共享影响或明确整体验收才扩大到全量。
- 硬件 smoke、SITL 与真实桌面是不同证据：ROS 实验使用与现场隔离的 domain 和 localhost；核对既有进程、端口及媒体路径，避免与实机同名流混合。隔离边界不明时先解决隔离，不运行会发送控制命令的测试。
- GUI 的 offscreen 测试不能证明现场 DISPLAY/XAUTHORITY 和真实窗口正常；只有涉及桌面交付时再做实际桌面核验。
- 飞控、避障、视频、Tag 为独立服务；按实际影响重启。连接地面站可能申请租约或维护参数，不以“点击连接”代替只读台架检查。

## 两个常见判断

- **只更新外参文件：** 校验所选飞机、文件及消费者；按当前实现决定重启哪些进程。无需因为是“部署”就重建所有包或执行飞行验收。
- **接口源码已经一致但 GUI 行为仍旧：** 追踪生成接口、安装前缀、进程启动环境和实际动态库；不要反复复制源码，也不要直接提高接口容错来掩盖版本混用。
