# ROS2–ArduPilot 故障取证

产出可追溯的事实、受证据支持的故障机制、尚未区分的原因，以及下一步能区分原因的最小实验。证据不足时交付明确的范围和缺口，不用推测补齐根因。

## 确定事件与证据范围

- 按当前用户问题确定设备、会话和异常时间段；遵守适用 AGENTS.md，MEMORY 仅提供当前基线与已知风险线索。回溯事故时优先识别事发版本、参数和运行环境，不能用今天的源码替代事发实现。
- 先盘点已给材料的来源、原件身份、起止范围、采样/缺失及重启边界。跨设备复制重要原件时校验完整性，派生图表和解析结果与原件分开保存；不改写原始时间戳或用处理后材料替代唯一原件。
- 查历史先看 `agent/report/topics/INDEX.md` 的相关专题，没有对应专题时查报告总索引，再定向读取相关报告及必要证据路径；不扫描整个 agent/codex 或 agent/grok。这些本机资料缺失不阻止分析用户提供的日志或当前源码。
- 沿异常所在链路取证，按需读 [证据与解释边界](references/evidence.md)，不要每次同时检查飞控、媒体、网络全部子系统。

## 对齐后再判断

- 区分设备启动时间、ROS 样本时间、DDS 源/接收时间、主机单调时间、墙钟及落盘时间；用共同事件与会话建立对应。校时或重启需要分段，无法可靠对齐时报告误差范围，不能强排毫秒级因果顺序。
- 比较同一会话、同一物理量、同一参考点/坐标/单位。特别区分 Odin 原始观测、extnav 输出、飞控实际接收值和 EKF 融合值；也区分控制参考、发送命令、飞控接受和实际运动。
- 从最早可观测分歧向上下游追踪，标出正常段和恢复段；“第一条异常日志”不一定是最初故障。把触发条件、故障放大机制和保护动作分开，不把 LAND 等下游结果自动当成根因。
- 对竞争假设寻找可反驳证据：例如上游停流与回调阻塞分别需要哪里有/无样本。优先复算现有材料或最小离线复现；证据不能区分时保留多个假设，说明缺少哪个观测。

## 实验与结论边界

- “分析原因”不等于授权部署修复、调阈值或改变飞控参数。远端只读取证也先确认目标；未指定飞机按项目约定使用 refresh，不可达不自行换机。先保全日志再考虑重启，避免丢失易失证据。
- 实机解锁和起飞只能由用户操作，不用上位机巡检命令间接触发。必要的新实验优先离线或隔离 SITL；涉及实机操作时保持当前任务授权边界。
- 已授权修复时，依据证据在故障对象上最小修改，验证原失败场景；不能靠放宽保护、替换输入、改变验收标准或另建旁路来宣称修复。
- 报告区分事实、推断、待验证假设与缺失数据。给关键结论附来源文件、会话/时间窗和必要的计算方法；说明复现条件、反例及尚不能推广的部分。
- 不把“离线复现机制”写成“已确认现场唯一根因”，不把台架/SITL通过写成实飞验收。后续证据改变判断时保留历史报告身份，并更新当前结论与风险。

按[报告工作流](../project-maintenance/references/report-workflow.md)保存报告及精简复算材料，并更新受影响专题，使用项目 Python 环境。MEMORY 只更新仍影响接续的基线、风险和证据入口，不写调试流水；不另造日志框架或把一次性分析脚本变成默认运行依赖。
