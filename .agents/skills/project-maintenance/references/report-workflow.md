# 报告工作流

适用于本项目新增的执行、分析、部署、研究和维护报告。旧报告保留当时正文，不批量迁移。报告与专题仍为本机 `agent/` 资料；缺失时只建立当前任务所需入口，不虚构历史。

## 是否生成报告

- 只有项目交付的编程语言代码发生实质修改时默认生成报告，包括实际逻辑、接口、算法或可执行行为的新增、修改、删除；Python、C/C++、Shell等均适用，不按改动行数判断。
- 聊天、评估、分析、调研、代码审阅或仅运行测试，默认在聊天中交付；纯文档/技能规则、配置/参数、部署同步、清理归档，以及仅注释/格式/无逻辑变化的重命名，也不默认生成报告。为分析或验证临时编写的脚本不算项目交付代码，不使分析任务变成默认报告任务。
- 用户明确要求报告时按其要求产出，明确不要报告时也遵从。保存原始证据、必要复算材料，或按需维护已有专题/MEMORY，不等于必须新增报告；不得另存一份同类任务总结绕过此规则。
- 后续格式、索引与 `--report` 要求只对确实需要新增报告的任务生效。没有新报告时不虚构报告路径、不为检查器补报告，也不强制更新报告总索引。

## 查阅与收尾

- 查历史先查看 `agent/report/topics/INDEX.md` 的相关专题，再按推荐阅读定向取证；没有相关专题时搜索 `agent/report/INDEX.md`。普通任务无需通读全部索引或过程目录。
- 新报告仍写入 `agent/report/report-<日期>-<唯一任务标题>.md`。作者完成报告、总索引、受影响专题的增量维护；移动报告同时修正专题、MEMORY等入链和正文相对链接。
- 有持续多轮调查、实现、部署关系时复用或新建专题；一次性小修改允许“主专题：无”。专题用稳定英文短名，不用可重复的Task编号作为唯一身份。每份报告最多一个主专题，跨专题影响可在正文中链接说明。
- 专题有关联时必须收录新报告；新认识改变结论、验证边界或未解决项时更新对应内容。没有新认识时仅补关联记录，不为刷新日期而改写结论。
- MEMORY只保留每次接续必须知道的基线、逐机差异、重要风险及专题入口；专题保存问题的综合认识；报告保存当次证据；稳定设计和使用说明进入docs或模块README。避免复制四份相同正文。
- 历史报告不因新证据被改写成“当时已解决”。在专题中说明哪项判断被补充、修正或替代，以及仍适用的条件；修复一条路径不等于关闭整个问题。

## 新报告格式

标题后、正文前放以下四行（位于文件前30行，每行独立）。类型从“实现、修复、分析、部署、研究、维护”选择，可用 ` / ` 组合；专题和承接报告使用Markdown相对链接，没有则写“无”。验证范围写实际环境和未覆盖的关键边界。

```markdown
<!-- 本次任务的简要交付记录。 -->
# 任务标题

类型：修复 / 部署
主专题：[遥测停顿](topics/telemetry-stall.md)
承接报告：[上轮分析](history/report-某日期-某任务.md)
验证范围：本地和ARM隔离验证；未实飞

## 结果与变更

说明本次结论、必要的版本/设备范围及实际变更。

## 验证与未完成项

写实际结果、限制及必要证据入口；小任务可合并正文，不强制固定章节。
```

总索引仍保留日期、报告、摘要三列，每份报告只登记一次，摘要≤100字。专题可再次引用同一报告，这不是总索引重复。根目录报告最多50份，超限按参考价值移入history；专题页、规范、索引和附件不计入。history表示存放位置，不代表结论失效或低价值。

## 专题格式

`agent/report/topics/INDEX.md`只列专题入口及一句当前摘要；专题正文使用 `topics/<稳定短名>.md`，新增时登记入口。保持简短，包含：

- 当前结论与适用版本/设备、证据更新时间。
- 已确认事实、已完成处理及尚未解决问题，附支持这些判断的报告链接。
- 推荐阅读顺序：先读哪几份、各自解决什么问题；可附其余关键报告的简短关系。
- 下一步最小核验，以及必要的唯一原始证据入口。正文用Markdown链接指向实际存在的原件或证据目录，不把过程目录全部列入保留范围。

## 交付检查

有新报告时从仓库根目录执行（多份新报告重复传 `--report`）：

```bash
.venv/bin/python .agents/skills/project-maintenance/scripts/audit_reports.py . --report agent/report/report-<日期>-<任务标题>.md
```

仅修改已有报告、专题或索引时，按需运行不带 `--report` 的同一命令；没有报告资料变更的普通任务无需运行此检查。

检查器只读，检查数量、总索引、专题入口/本地链接及新报告字段、主专题反向收录、承接报告链接。2026-11-07及以前的无字段报告作为旧格式兼容；本日新报告通过 `--report` 明确检查，之后日期自动检查，已采用新字段的报告也自动检查。旧报告无需补齐字段。

检查器不判定结论真假，也不以修改时间证明专题维护完成。由作者核对本次证据是否改变专题认识；只有用户明确要求项目级维护或跨任务整理时，才调用维护技能做整体复核。日常报告、索引、专题、MEMORY增量维护及检查器执行不触发该技能；数量超限时按规则定向归档，不自动扩展为全仓清理。检查结果有既存问题时说明范围，不为了通过检查删除唯一证据、改写历史结论或无关资料。

规则要求新增报告时收尾执行检查；本流程没有安装自动结束钩子，不能声称代理漏执行时仍会被系统强制拦截。
