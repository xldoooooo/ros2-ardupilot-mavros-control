# ROS2–ArduPilot 项目维护清理

维护项目资料、可重建产物及测试体系，保留实际可运行环境、唯一资料和接续入口。允许修正测试代码、夹具、分组及测试构建/执行入口；不借维护修改产品程序逻辑、运行参数或项目功能。

用户点名本技能，或明确要求项目级清理、批量归档、跨任务资料整理时使用；默认一并检查并修正测试维护问题，用户明确限定仅归档或其他局部范围时遵从该范围，不因调用而自动全仓清理或运行全套测试。日常报告/索引/专题/MEMORY的增量维护和检查器执行直接遵守报告工作流，不升级为完整维护任务，也不按报告数量或时间自动调用本技能。

## 确定边界与当前状态

- 读取当前用户要求、适用的 AGENTS.md、MEMORY 和清理任务文件。用户最新约束优先，不照搬旧报告中的数量上限、地址或服务状态。
- 先用 `git rev-parse --show-toplevel` 核对Git根和清理范围；目录不是独立Git项目时，跳过不适用的Git步骤，不能把父仓库当作授权清理对象。
- 核对 Git 的 staged / unstaged / untracked 状态，记录已有改动；区分本次维护与此前功能修改。需要证明未触碰程序时，先保存相关文件哈希及少量有价值的 diff，避免再复制一套大备份。
- 本次明确清理 agent/codex 等目录时可定向检查；不要把清理授权扩展到其他项目、远端机器、全盘日志或生产服务。
- 从 du 分层统计与大文件清单入手，并查看活跃进程、配置/安装入口引用。检查剩余大目录的组成，不能删完缓存就以“保留证据”为由留下大量可重建输出。
- 读取 [本项目约定](references/ros2-ardupilot.md)。`agent/` 和MEMORY为本机忽略资料，新检出副本可能没有任务/索引；缺失时按本技能与当前用户要求工作，不把历史资料缺失当作项目无法维护。

## 清理临时文件和备份

按来源与重建条件判断，不按文件扩展名、日期或目录名字批量删。

| 对象 | 决策依据 |
| --- | --- |
| 隔离实验的 build/install、对象文件、下载缓存、重复源码/测试构建树 | 核对运行、安装及当前测试依赖；移除可重建的测试产物时确认重建入口有效，并在后续验证前重建。不要误删当前正式环境或唯一源文件。 |
| CSV、点云回放缓存、抽帧、转码/校色试片、合成测试录像、SITL日志 | 原输入和必要脚本/参数/版本仍在即可清理，保留紧凑结果摘要；旧报告引用本身不构成保留理由。 |
| 实飞原始bag/BIN/录像、设备标定、飞控参数、唯一源码与原始交付 | 保留。只有确认另有完整相同原件时，才清重复副本。模拟BIN与实飞BIN须依据来源区分。 |
| 备份、压缩包、同步bundle | 哈希或Git对象证明重复后去重；保留关键恢复节点，不仅凭名称相似认定重复。 |
| 旧源码checkout | 先核对 HEAD、dirty/untracked、仅本地提交和共享 worktree。保存唯一修改及重建所需版本信息后，才移除可恢复的副本；不能破坏其他worktree的Git对象库。 |
| 正在使用的预览、捕获或运行环境 | 保留所需内容；若清理必须中断它，先按用户授权范围处理，不擅自停止其他工作。 |

- 原输入已丢失、来源不明或恢复条件不成立的对象单列保留，不把不确定项混进批量删除。
- 大批删除先生成精确路径、原因、大小清单；去除父子重复，拒绝清理根目录、路径越界或经符号链接跳出范围。只删除已审定对象，不使用整仓 git clean/reset。
- 对保留的重要原件按需要记录并复核哈希。统计逻辑内容大小、du占用或磁盘空闲变化时说明口径，不混为“精确释放量”。

## 测试维护

- 先读仓库 [测试指南](../../../tests/README.md)，核对 `tests/run.py` 的影响映射、分组、测试收集和实际源码。项目级维护检查全部组的职责与主要测试；局部维护沿受影响功能及共享依赖检查，不仅看本轮变更文件。
- 判断分组是否仍与功能边界一致，是否漏掉共享模块的消费者、包内原生测试或独立测试入口；修正错误归组和遗漏映射。混合多种功能或执行条件的测试按职责拆分，复用夹具放公共支持模块，避免测试文件互相导入。同步测试指南，保持映射只有一个权威来源。
- 对照当前行为检查过时、重复、无效、错误或不合理的用例；重点识别只比源码字符串、冻结无关配置/界面细节、未执行目标路径却通过等问题。直接修正用例和断言；仅在确认需求已废弃或覆盖确实重复时删除，不因测试旧、慢或失败就删除。
- 保留独立的期望值和必要的核心行为覆盖，避免按实现复制一遍算法。检查单元与集成标记是否符合真实依赖，外部设备、网络、ROS、媒体进程和本机状态是否隔离；使用临时数据和受控进程，不读取或污染现场标定、用户偏好、上传队列等真实状态。
- 按当前指南先用 `bash tests/run.sh --files <相关路径...> --list` 核对选择，再运行受影响组及必要层级；显式指定路径以免混入无关并发改动。修改原生接口/源码或清理其产物后，先按指南运行 `bash tests/build_native.sh` 重建匹配的接口与消费者，再验证原生及集成测试。独立测试入口另行核对，不把未收集当通过；共享逻辑广泛调整或明确全面验收时才运行全套。
- 失败时区分测试错误、产品缺陷、旧构建产物与环境缺失。修正测试及构建/执行入口的真实问题，不降低产品要求、放宽关键断言或新增跳过来制造通过；产品缺陷超出维护范围时如实交付定位与未通过项。测试维护不授权连接实机、启停现场服务、解锁或起飞。
- 交付说明修正/删除/拆分的依据、分组变化、实际运行范围及结果，列明未运行、跳过和受阻原因。无需为每次维护新增回归测试或固定测试数量；测试代码发生实质逻辑修改时按项目报告规则处理，纯检查与运行不自动生成报告。

## 文档、MEMORY 与报告

- README 只保留项目用途、功能、部署/使用入口。精简前若有手工现场笔记、独有命令或用户补充，将原文完整保存到 docs 下的唯一历史快照，验证字节一致并添加入口；不因文字过时直接删掉这些原始记录。已有相同快照可复用。
- 当前文档按实际源码/配置纠正旧版本、废弃路径和重复说明；原厂资料、原始协议与历史快照保留身份，不伪装成当前操作指南。历史快照不为消除旧链接警告而改写原文。
- MEMORY 整理为当前基线、逐机差异、关键恢复节点和未解决风险，删除过程流水与重复历史；不把仅有诊断证据的风险改写成已修复。
- 报告与专题共用[报告工作流](references/report-workflow.md)。报告作者维护本次增量；本技能复核重复专题、遗漏的新证据和未解决项，精简专题并将稳定知识整理入正式文档。不为每个小任务建专题，不批量改写旧报告；归档不降低证据地位。
- report 根目录**最多50份报告**，用户另有明确上限时按最新值执行；AGENTS、INDEX与同份报告附件不重复计数。仅本轮需要报告时预留位置，超限按当前参考价值移入 history，不仅按日期排序；不为凑满50份回迁历史资料。
- 报告移动后同时维护其指向 assets/codex/仓库文档的相对链接、专题/外部文档/MEMORY的入链、关联附件和 INDEX。每份报告在总索引只列一次，摘要≤100字；专题可引用同份报告，保持历史正文的当时结论。
- 本轮涉及报告/索引/专题维护时，在仓库根目录运行 `.venv/bin/python .agents/skills/project-maintenance/scripts/audit_reports.py . --max-current 50`；只有新增报告时追加 `--report agent/report/<本轮报告文件名>`。检查器只读，不能判定结论真假；旧报告附件与正文链接仍需按本次移动/清理范围核对。新副本没有本地报告时不凭空制造历史索引。
- 交付前从磁盘重新统计，纳入本轮实际新增及并发产生的报告，不沿用清理前的固定计数。

## Git 与交付

- 核对被跟踪的运行导出、二进制包、缓存及本机资料；确属本地文件时用精确ignore和取消跟踪，保留本地原件。已有跟踪文件不会因新增ignore自动消失，须分别验证索引和忽略结果。
- 不把静态SDK库、镜头存档或未接入构建的有差异参考源码直接当垃圾。不要借清理重写历史或恢复旧stash覆盖当前项目。
- 已有功能/配置改动可按用途审阅归类；是否提交、推送由本次要求和明确仓库约定决定。不要为了工作区“干净”而丢弃、偷偷修写或夹带现场改动；staged修改与工作区删除并存时以核实后的最终结果组织提交。
- 验证与本次影响相称：文件/哈希、快照、索引、路径、Git状态优先；已有功能改动需要提交时做必要的定向检查。纯文档/删除派生产物不为凑数量重复跑全套测试。
- 默认在最终回复交代清理范围、实际删除和剩余占用、归档/文档/Git结果、原件保留依据、真实验证、未完成项及下一批可清对象；剩余大目录说明其原始数据/有效依赖组成。仅用户明确要求报告或本轮修改了实质编程语言代码时，按共用工作流新增简报；纯清理不自动产出报告。
- 按实际变化维护MEMORY、专题与索引，确认本机资料仍在、源码/参数未被意外改动、报告数≤上限；发生提交/推送时核验实际HEAD和远端，不把计划当结果。
