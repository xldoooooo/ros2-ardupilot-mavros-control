# ROS2–ArduPilot 项目维护清理

本技能仅用于所属仓库，维护范围来自 `agent/task/14-trim.md` 及本项目实践。技能随仓库保存在 `.agents/skills/project-maintenance/`，不另装到个人全局目录。纯清理保留实际可运行环境、唯一资料和接续入口，不修改程序逻辑、运行参数或项目功能。

## 确定边界与当前状态

- 读取当前用户要求、适用的 AGENTS.md、MEMORY 和清理任务文件。用户最新约束优先，不照搬旧报告中的数量上限、地址或服务状态。
- 先用 `git rev-parse --show-toplevel` 核对Git根和清理范围；目录不是独立Git项目时，跳过不适用的Git步骤，不能把父仓库当作授权清理对象。
- 核对 Git 的 staged / unstaged / untracked 状态，记录已有改动；区分本次维护与此前功能修改。需要证明未触碰程序时，先保存相关文件哈希及少量有价值的 diff，避免再复制一套大备份。
- 本次明确清理 agent/codex 等目录时可定向检查；不要把清理授权扩展到其他项目、远端机器、全盘日志或生产服务。
- 从 du 分层统计与大文件清单入手，并查看活跃进程、配置/安装入口引用。检查剩余大目录的组成，不能删完缓存就以“保留证据”为由留下大量可重建输出。
- 读取 [本项目约定](references/ros2-ardupilot.md)。`agent/` 和MEMORY为本机忽略资料，新检出副本可能没有任务/索引；缺失时按本技能与当前用户要求工作，不把历史资料缺失当作项目无法维护。

## 清理临时文件和备份

按来源与重建条件判断，不按文件扩展名、日期或目录名字批量删。

| 对象 | 决策依据 |
| --- | --- |
| 隔离实验的 build/install、对象文件、下载缓存、重复源码/测试构建树 | 确认没有实际运行或安装依赖后清理；不要误删当前正式环境或唯一源文件。 |
| CSV、点云回放缓存、抽帧、转码/校色试片、合成测试录像、SITL日志 | 原输入和必要脚本/参数/版本仍在即可清理，保留紧凑结果摘要；旧报告引用本身不构成保留理由。 |
| 实飞原始bag/BIN/录像、设备标定、飞控参数、唯一源码与原始交付 | 保留。只有确认另有完整相同原件时，才清重复副本。模拟BIN与实飞BIN须依据来源区分。 |
| 备份、压缩包、同步bundle | 哈希或Git对象证明重复后去重；保留关键恢复节点，不仅凭名称相似认定重复。 |
| 旧源码checkout | 先核对 HEAD、dirty/untracked、仅本地提交和共享 worktree。保存唯一修改及重建所需版本信息后，才移除可恢复的副本；不能破坏其他worktree的Git对象库。 |
| 正在使用的预览、捕获或运行环境 | 保留所需内容；若清理必须中断它，先按用户授权范围处理，不擅自停止其他工作。 |

- 原输入已丢失、来源不明或恢复条件不成立的对象单列保留，不把不确定项混进批量删除。
- 大批删除先生成精确路径、原因、大小清单；去除父子重复，拒绝清理根目录、路径越界或经符号链接跳出范围。只删除已审定对象，不使用整仓 git clean/reset。
- 对保留的重要原件按需要记录并复核哈希。统计逻辑内容大小、du占用或磁盘空闲变化时说明口径，不混为“精确释放量”。

## 文档、MEMORY 与报告

- README 只保留项目用途、功能、部署/使用入口。精简前若有手工现场笔记、独有命令或用户补充，将原文完整保存到 docs 下的唯一历史快照，验证字节一致并添加入口；不因文字过时直接删掉这些原始记录。已有相同快照可复用。
- 当前文档按实际源码/配置纠正旧版本、废弃路径和重复说明；原厂资料、原始协议与历史快照保留身份，不伪装成当前操作指南。历史快照不为消除旧链接警告而改写原文。
- MEMORY 整理为当前基线、逐机差异、关键恢复节点和未解决风险，删除过程流水与重复历史；不把仅有诊断证据的风险改写成已修复。
- report 根目录**最多50份报告**，用户另有明确上限时按最新值执行；AGENTS、INDEX与同份报告附件不重复计数。为本轮新简报预留位置，超限按当前参考价值移入 history，不仅按日期排序；不为凑满50份回迁历史资料。
- 报告移动后同时维护其指向 assets/codex/仓库文档的相对链接、外部文档/MEMORY的入链、关联附件和 INDEX。每份报告只列一次，摘要≤100字；保持历史正文的当时结论。
- 在仓库根目录运行 `.venv/bin/python .agents/skills/project-maintenance/scripts/audit_reports.py . --max-current 50`，核对直属报告和表格索引。检查器只读；附件与正文链接另行核对。新副本没有本地报告时不凭空制造历史索引。
- 交付前从磁盘重新统计，纳入本轮简报和并发新增报告，不沿用清理前的固定计数。

## Git 与交付

- 核对被跟踪的运行导出、二进制包、缓存及本机资料；确属本地文件时用精确ignore和取消跟踪，保留本地原件。已有跟踪文件不会因新增ignore自动消失，须分别验证索引和忽略结果。
- 不把静态SDK库、镜头存档或未接入构建的有差异参考源码直接当垃圾。不要借清理重写历史或恢复旧stash覆盖当前项目。
- 已有功能/配置改动可按用途审阅归类；是否提交、推送由本次要求和明确仓库约定决定。不要为了工作区“干净”而丢弃、偷偷修写或夹带现场改动；staged修改与工作区删除并存时以核实后的最终结果组织提交。
- 验证与本次影响相称：文件/哈希、快照、索引、路径、Git状态优先；已有功能改动需要提交时做必要的定向检查。纯文档/删除派生产物不为凑数量重复跑全套测试。
- 生成唯一执行简报：清理范围、实际删除和剩余占用、归档/文档/Git结果、原件保留依据、真实验证、未完成项及下一批可清对象。剩余大目录说明其原始数据/有效依赖组成。
- 维护MEMORY与索引，确认本机资料仍在、源码/参数未被意外改动、报告数≤上限；发生提交/推送时核验实际HEAD和远端，不把计划当结果。
